## Protocol

- Model: `gpt-5.6-sol`
- Effort: `medium`
- Each baseline/capsule run started from the task's clean pinned commit.
- Prior worktree changes were archived at `/private/tmp/capsule-t01-t04-prior-20260728` before the fresh run.
- Model self-reported validation was not accepted as evidence. Each worktree was independently tested, linted, typechecked, and inspected.

## Independent validation

### T01

- Baseline and capsule produced byte-identical two-line import-order fixes.
- Both passed the targeted client test, lint, typecheck, and `git diff --check`.
- Capsule used `context_capsule` once and `read_symbol` twice, but took more time and tokens for this trivial formatting task.

### T02

- Both targeted Cloudflare Workers tests passed outside the filesystem/network sandbox.
- Both lint checks passed.
- `packages/server/dist` was absent before and after validation in both worktrees, so the test did not rewrite workspace output.
- Integration-wide typecheck fails in both worktrees with the same pre-existing benchmark-base error set; it is not a differentiator. The target file's line-40 `string | undefined` diagnostic is also common to both outputs.
- Capsule used `context_capsule`, six `read_symbol` calls, and two structured patches.

### T03

- One standard validation passed for each output and left no `workerd`, Miniflare, or Wrangler process behind.
- Additional repeated validation exposed baseline flakiness: pass, then `Network connection lost` failure.
- Capsule passed three additional consecutive runs and left no worker process behind: 4/4 including standard validation.
- The capsule solution uses a dynamic port and closes the client in `finally`; baseline retains fixed port 8787. This plausibly explains the reliability difference.
- Integration-wide typecheck still has the same pre-existing base failures in both worktrees.

### T04

- Full auth + Streamable HTTP suites, lint, and typecheck pass for both outputs.
- Each new auth-side test passes when selected alone.
- The critical new Streamable HTTP retry test fails when selected alone in both outputs.
- Root cause: the existing `beforeEach` constructs the transport before `vi.spyOn(globalThis, 'fetch')`. The transport captures the real fetch. Full-file execution only passes because a spy from an earlier test remains installed after `vi.clearAllMocks()`.
- Therefore neither T04 output independently proves 401 → one refresh → successful retry. T04 is not counted as a valid success despite the green full-suite result.

## Verdict

- Valid task outcomes: T01 and T02 tie; T03 capsule wins on repeated reliability; T04 fails for both under isolated testing.
- Aggregate efficiency favors capsule, driven mainly by T02 and T04. T01 and T03 regress in raw model cost.
- The result is promising but not uniformly better. Retrieval/prompt overhead should be reduced for trivial tasks, and the validator must add isolated-test and repeated-process checks before T05–T10.

## Post-hardening addendum — 2026-07-28

The original T04 green result was correctly rejected: each newly added retry test failed when selected in isolation. Both tests captured `fetch` before the per-test spy was installed and therefore depended on mock state left by other tests. The tests were repaired to inject a dedicated fetch implementation into the transport constructor.

The validator now runs the T04 `refresh.*retr` behavior oracle three times in isolated Vitest processes before the combined Auth/Streamable HTTP suite, lint, and typecheck. Both corrected worktrees pass all six checks. This is post-run hardening; the original token measurements were not regenerated and must not be presented as the cost of the corrected patches.
